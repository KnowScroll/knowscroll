# Privacy & history (P02, #345)

`/account/privacy` is in the existing account Stack and is linked from Account. It mounts the
manager-owned `privacy` session, so the minimal exact unknown request survives a privacy-triggered
AccountScope remount while all old scope data/resources are purged. A new page/controller reads
latest status; it never automatically creates or retries a clear.

The committed P02 consequence/preservation copy and irreversible acknowledgement checkbox precede
the typed fixed confirmation command. Clear removes exploration history/derived plans/universe;
Keep items/places and Social stay. Accepted, pending, failed, unknown, not-recorded and live-complete
states have distinct copy. Unknown exposes only explicit same-body retry/status checking; a read
cannot promise a delayed send is absent. Current account/epoch/selector/receipt lineage is checked
in client-core. Session recovery uses the actual session read, never an ACK-derived epoch.

Context already sent to an AI provider cannot be recalled. Live completion is separate from backup,
provider-copy and offline-device expiry, and no unverified expiry date is shown. Recording pause,
export and account deletion are labelled unavailable here. There is no generic erasure selector,
time range, artificial percentage or claim of full privacy completion.

Component fixtures exercise real routing, manager/provider remount, explicit confirmation, unknown
same-body retry and live-versus-external completion copy. They run only in hosted Actions and are
not real account/database/device acceptance. Root owns API/worker composition, the disposable-account
connected journey and deployment acceptance. No Keep/encounter/direct renderer is changed here.
