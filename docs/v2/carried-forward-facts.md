# Facts carried forward from the v1 documentation

The v1 docs were removed from this branch so they cannot be mistaken for current rules. These are the facts and owner rulings from them that are still true or still binding, quoted with their **v1 source path**. Every source is recoverable with `git show legacy/v1-final:<path>`.

Where v2 changes one of these, `decisions.md` records the change; this file is not edited to match. Some entries describe the v1 runtime that still runs on the VPS until v2 replaces it (marked "v1 runtime"). Collected 2026-10-19 by a read-only inventory of `dev@106c4701`.

> PRs target `dev`. Never update `main`: only the owner and XZNON promote to live (`scripts/promote.sh live`); `.claude/hooks/refuse-main-update.mjs` enforces this for agents. **CF-02 Who may promote, and the honest limit.** Source `docs/plans/environments/00-status.md`:

**CF-03 The repository is public on purpose.** Sources `CONTRIBUTING.md` and `docs/CHECKPOINT.md`:

> GitHub Actions stopped starting jobs mid-wave: "The job was not started because recent account payments have failed or your spending limit needs to be increased." ### 3D. Providers (MiniMax, fal)

**CF-50 MiniMax subscription route, quota and limits.** ADR-0011, `docs/operations/minimax-certification.md`, handoff §2.2, ADR-0041 §7-8:
* Route: "`MiniMax-M3` through the fixed official Anthropic-compatible route `https://api.minimax.io/anthropic/v1`" (production worker path posts to `.../anthropic/v1/messages`), "an `sk-cp-` subscription key from the process environment only"; "No PAYG" ("the tool never buys Credits or falls back to PAYG"), no endpoint override, no redirects, no automatic retry.
* Quota preflight before every request: GET `https://www.minimax.io/v1/token_plan/remains`; require provider status zero, one `general` entry, and **finite 25-100 % remaining in both the current interval and weekly windows**; "Missing/ambiguous/exhausted quota fails closed"; "the zero-valued total counters ... are deliberately ignored". "Other tools share quota, so preflight is an observation, not an atomic vendor-side reservation."
* "The owner reports a token plan of 300 million tokens per five hours" - not evidence of an allowance ("The owner-reported token allowance does not establish arbitrary cash spending permission", `development.md`).
* Per-request caps: the Scroll writer sends at most 16,384 bytes with `max_tokens` 4,096 (ADR-0041 §3); the certification runner also used 60 s per request and 5 min per run, 4 serial requests, 100,000 reserved units (ADR-0011). A request is recorded durably *before* dispatch; an unresolved dispatch is "unknown" and is never re-sent.
* Session ledger (old tool): `$KS_DEV_ROOT/minimax-answer-session-ledger.json` (`sessionCap`, `used`, `runs`; missing ledger is refused). 155 requests were available at the 2026-09-24 handoff (5 left of the original 40 + 150 added), "72 -> 74 of 190" on 2026-09-25. Per-world supply cap: `install-supply ... --request-cap 150` ("at most 150"), key in `/etc/knowscroll/secrets/shared/minimax.env`, copied once by hand from the owner's Mac.
* Models: `MiniMax-M3` is "the only vision model" (also the 1M-context one); `MiniMax-M2.7` / `MiniMax-M2.7-highspeed` are text-only (legacy D-006; provisional until benchmarked). M3 "additionally reports `reasoning_tokens` and `cached_tokens`".

**CF-51 `<think>` blocks and thinking.** `docs/archive/legacy-decisions.md` D-019:
> **One finding that changes the pipeline: all three models emit `<think>…</think>` blocks.** A 16-token cap was consumed entirely inside the reasoning block, so no answer survived. Every structured-output call must therefore either disable thinking or strip the reasoning prefix before parsing, and every `max_tokens` must budget for reasoning on top of the answer. A schema call that "returns nothing" will be this, not a schema failure.

Current code does both: ADR-0041 §3 "`max_tokens` is 4,096 and thinking is disabled", §4 "bare or as the only content of one fenced block, after `<think>` blocks are dropped"; `packages/core/src/reasoning/wire.ts` `wholeObject()` strips `/<think>[\s\S]*?<\/think>/g`. For tool/continuation use, ADR-0011/0042: "Native provider thinking/tool blocks must survive internal continuation", keep "raw native thinking/tool blocks only in protected process memory" (`apps/worker/AGENTS.md`), "Do not synthesize usage fields", "`thinking: adaptive`" for the tool-call case.

**CF-63 Cutroom script rules (what makes a script orderable).** From `content/reel-scripts/*.json`, ADR-0024, ADR-0050, `00-status.md`:
* A script is `{id, authoredBy, approval:{ref, approvedBy:'owner', approvedAt}, brief:{version:1, worldId, narration:[{text, claimIds[]}], claims:[{id, role: main|supporting}], claimSources:[{claimId, assetId, assetRevision}], criteria:{mustShow[], mustNotShow[], depictionPolicyVersion:'policy-3'}, style:{id, version, text}, title, summary}}`; each `mustShow` has `{id, text, type:'presence', claimId}`; typical `mustNotShow`: a recognisable real-world public figure, written words or labels.

* **Cutroom needs a minimum of six narration units**: the `approval.ref` of `sunburn-v4.json` and `tides-v4.json` says "v3 stopped because Cutroom needs six units" and commit `8982391f` (#219) is titled "six sentences or more, as Cutroom needs". * **Repetition gate (ADR-0024)**: template and argument fingerprints computed from the brief's structure are compared "against every other Reel that already carries fingerprints, whatever its availability"; "A match on either fingerprint fails the gate". The owner kept the rule ("B: keep the rule", 2026-10-09), so "every new script needs a structure no fingerprinted Reel has". This is why tides-v2/sunburn-v2 were refused.
