Conversation detail

Asha ↔ Ravi. A plain 1:1 conversation: messages, exact content cards, and “Start a thread” to turn a shared Reel into a content thread (C04). A failed message stays one bubble; reconnect fills gaps in order.

Prototype · design data

Route & origin

/talk/:conversationId from C01, the H01 “Open” toast, a notification or the H02 “Reply in Talk”. Opens at first unread. Shared cards deep-link to /e/:id?t=12 as Ravi’s own encounter.

Actions

Primary: write and send, open a shared card. Secondary: Start a thread (→ C04: the shared Reel becomes a content thread with this conversation’s members, or pick more people in H01), Retry a failed message, ⋯ Mute / Report / Leave / Block, long-press a message to reply, report or share a moment.

States & overlays

loading · ready · typing (real signal only) · sending · sent · failed → retry · offline queued · reconnecting → catch-up divider · withdrawn card inside a bubble · blocked · membership lost (composer removed).

Commands · observations

CMD message.send{conversationId, requestId}
CMD message.retry{sameRequestId}
CMD block.user · report.message · conversation.leave
CMD thread.create{members: this conversation, root: cardAssetRevision}
Realtime: socket reconnect cursor fetches missing range; messages ordered by server sequence.

Restore

Keeps scroll position and the unsent draft per conversation. After reconnect the view stays where the reader was and inserts the “While you were away” divider — it never jumps to the bottom on its own.

Accessibility & platform

New messages announced politely via a live region; “Not sent, Retry” is a real button. Composer stays above the platform keyboard (native) and accepts Enter to send / Shift+Enter newline (web). Native back returns to C01.
