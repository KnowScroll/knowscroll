E06

Format conversion

Same explanation, other representation. An existing sibling opens at once; a missing one is prepared quietly while the original keeps its place.

Prototype · design data

Route & origin

Switch in any encounter’s top bar. Existing: /e/:id → /s/:siblingId. Missing: stays on /e/:id; the request lives in Keep → Requested (E07).

Actions

Primary: tap Reel / Scroll. Secondary: Back to Reel chip, Cancel request, Open / Later on the ready toast. Format change is tap-only — never a swipe.

States & overlays

sibling exists · preparing (striped segment + quiet chip) · ready toast · cancelled · unavailable (“This one can’t be made as a Scroll”, Reel unchanged). Toast auto-hides to the request chip; it never steals focus.

Commands · observations

CMD format.switch{to: scroll|reel}
CMD format.request{explanationId, to} · request.cancel
OBS toast.shown · scroll.block_coverage

Restore

Reel playhead (0:31) and Scroll anchor are stored separately per explanation; switching back resumes each paused at its own place. Both formats share one explanation identity, so reading both isn’t double-counted.

Accessibility & platform

Segmented control: role group, aria-pressed; preparing segment announces “Scroll, preparing”. Ready toast is role=status (polite). Native: optional local notification only if enabled in P01. Web: toast also lists in the page’s notification region.
