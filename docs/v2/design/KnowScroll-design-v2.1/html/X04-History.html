X04

Branch map (optional)

Only offered once a thread has grown several branches. The first what-if never needs it: cards in the chat are enough.

Prototype · design data

Route & origin

/t/:threadId/map from the thread header “Map” button, which appears only once the thread has several branches or perspectives. Never shown for a first exploration.

Actions

Primary: jump to any node (opens at your own position there). Secondary: filter Mine / Everyone / Suggestions, search, expand a collapsed group, close.

States & overlays

small map · large map with collapsed groups · group loading (skeleton) · suggestion not made · preparing · removed branch (shown as “Removed”) · empty search · offline (cached outline, jumps disabled for uncached nodes).

Commands · observations

OBS thread.map_opened · thread.map_filter{kind}
CMD branch.open{branchId} on jump
Lazy: GET groups by parent node, paged

Restore

The map is an overlay, not a history entry; closing it returns to where you were. Jumping pushes the target onto Back history. Filter and expanded groups are remembered per thread on this device.

Accessibility & platform

A nested list (tree role on web) with real headings — no canvas graph. “You” marks only your own position, never other people’s viewing. Arrow keys move through nodes; Enter opens. Desktop shows the same outline in a side panel (D03).
