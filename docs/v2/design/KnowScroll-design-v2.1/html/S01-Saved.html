S01–S02

Keep library & resume

Everything you kept, with the exact place you left it. Corrected, withdrawn and still-preparing items say so plainly; opening one restores your position without pretending you watched it again.

Prototype · design data

Route & origin

/keep tab root (filters as query: ?view=requested) · /keep/:itemId detail. Reached from the Keep tab, a saved-state banner, or E08 “See it in Keep”.

Actions

Primary: open/resume an item. Secondary: filter, Start from the top, See it in your universe, Share, Remove, account via avatar. Long-press a card for Remove / Share.

States & overlays

loading (card skeletons) · library · empty · corrected item · withdrawn item · requested/preparing item · offline (cached list, “may be out of date”) · remove failed (card returns + Retry banner).

Commands · observations

CMD keep.remove{itemId} · keep.open{itemId, anchor}
OBS keep.restored (session-only) · then normal reel/scroll OBS once content is visible

Restore

Resume opens the exact revision at the saved anchor (block ID or playhead) with interactive block state. A restoration is session state only; a new encounter begins only when content is actually visible — opening the detail page records nothing.

Accessibility & platform

Filters: toggle buttons with aria-pressed. Each card is one link whose name includes title, format and position (“Attention, slowly, Scroll, at Why squared?”). Native: swipe-to-remove has a visible Remove alternative. Web: list is keyboard-navigable; Delete key removes with undo toast.
