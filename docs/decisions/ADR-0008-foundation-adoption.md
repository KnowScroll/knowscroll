# ADR-0008 — Adopt the full product direction with explicit implementation status

Date: 2026-09-15. Status: accepted under the owner's delegated bootstrap authority.

## Context

The owner accepts the refined architecture direction, wants the full product/recommender preserved, and authorizes a new executable repository. Old sources mix proposed architecture, a web/SQLite implementation plan and different visual experiments.

## Decision

The full product definition remains authoritative for product outcomes and laws. The September 15 core-engine refinement is the accepted target direction. This repository's architecture entrypoint, ADRs and versioned executable contracts govern concrete implementation. Detailed target schema/threshold examples are not automatically production migrations. PROJECT-STATE and journey receipts report implementation and observed runtime separately.

The owner's Cosmos visual selection supersedes conflicting older kiosk/survey-sheet defaults. Product laws constrain illustrative growth mechanics: no attention-count Star, inferred learning, or agent-consensus truth. The old validation gate remains historical sequencing; current authorization permits this bootstrap, and full grammar validation remains #3 acceptance work. It is not a repeated permission gate.

## Alternatives and why

Copying the old repository as current would carry stale runtime claims and gates. Discarding it would lose the semantic/product architecture. A selected, hashed migration with a clear adoption overlay preserves both understanding and provenance.

## Consequences

Old sources remain untouched. Target detail is easy to find but not required for every session. Conflicts resolve in order: current owner instruction → product laws → current accepted ADRs and versioned contracts → architecture summaries → target examples → historical research. If a conflict would change a product law, record a proposed decision and seek the owner’s decision; do not silently reinterpret it.
