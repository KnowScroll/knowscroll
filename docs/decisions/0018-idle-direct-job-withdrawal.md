# ADR-0018 — Safely withdraw idle direct Jobs

Date: 2026-09-17. Status: accepted for #75 after independent Terra review of `273f42b`. Extends ADR-0012/0015. Implementation and runtime verification remain pending.

## Boundary

Existing internal execution primitives can leave a queued or recovered waiting direct Job without a live worker lease. The original fenced `withdrawJob` cannot close it. This adds two internal transaction helpers for an already authorized, original-session-bound direct Job. No public endpoint, new Job, retry, provider grant, answer, proposal or mobile control is added. A recorded/replayed Ask remains source-only.

`cancelIdleDirectJob(client, authScope, {jobId})` requires `authenticateAndLock` on the same client/transaction. It revalidates the immutable original session, exact device, universe/current epoch and live unrevoked session after every relevant wait. A different session cannot cancel this Job. A scoped `reasoning_context_job_session` lookup must return exactly one original session id before locking it; the generic optional `lockBoundContextSession` helper alone is insufficient. A missing original-session binding is ineligible; no binding is created or substituted. Both helpers re-read exact binding/scope after waits.

`expireIdleDirectJob(client, {jobId, universeId, privacyEpoch})` is a trusted worker operation, never a client-authentication substitute. It locks the original session row even if expired/revoked, and requires the actual Job deadline to have elapsed according to PostgreSQL `clock_timestamp()`. It checks current universe/Job epoch and original binding; it does not refresh a session or grant execution authority.

Both helpers use the caller's existing transaction. They lock universe → original session → Job → sorted Steps → sorted Attempts/accounting → scheduler/fairness resources → sorted physical buckets. Initial immutable binding lookup is read-only. The cancel helper rejects a different original session before acquiring a second session lock. The last authority/deadline/lease recheck occurs after resource waits and acquires no new lock. Errors roll back the caller's entire transaction, except the explicitly scoped scheduler savepoint refusal below.

Only `wake_kind='direct'` (fairness class remains independently one of the five existing `FAIRNESS_CLASSES`), status `queued` or `waiting`, with no healthy lease is eligible. A healthy worker winning claim first causes refusal; this operation never interrupts it. Running Jobs, even with an expired lease, first use the existing fenced recovery path. Recovery-waiting work may retain unknown accounting. Old terminal Jobs with no authoritative clock remain untouched. Unbound legacy/background Jobs remain outside this new authority. Existing live-worker `withdrawJob` is unchanged.

## Atomic closure and replay

Before changing any state, check graph structure and lock all closure resources. At the scheduler-resource phase, acquire `lockFairnessResources(client, attemptIds, universeId)` once for the complete affected policy union (scheduler rows ordered by policy; class rows by policy/class; affected-universe rows by policy/class/universe). Lock the Job's scoped ready row before physical buckets. These locks precede the final authority recheck and every mutation.

First close provably reserved, unconsumed Attempts as `not_sent` through existing release semantics, including revision-zero fairness refunds. A dispatch-committed Attempt becomes `unknown`; existing unknown/response accounting remains retained. Withdraw output and deactivate private Attempts. Only unfinished Steps are cancelled; existing succeeded/failed/cancelled/superseded Steps stay terminal. Never refund consumed reservations, remote concurrency or unknown liability by age. A valid not-sent refund may reduce negative debt; “preserve debt” forbids an arbitrary reset, not a proven refund. Late original usage remains settleable after withdrawal/private retirement.

After all refunds, a dedicated fairness-owned `finalizeIdleJobFairness(client, {jobId, universeId, attemptIds})` reads the already-locked ready row and affected attempt fairness lanes. It deletes membership at most once and decrements exactly that policy/class/universe count, rejecting a missing lane, underflow or a remaining-count mismatch. It uses this state table:

| State after deletion/refunds | Required mutation |
| --- | --- |
| Universe still has ready members | Preserve candidate cursor, class universe cursor, open slot and remaining allowances; preserve credit after any proven refund |
| Universe has zero ready members | Clamp its credit to `LEAST(credit,0)` and reset candidate cursor to0. If its class open slot names that universe, close it, set universe remaining to0 and advance class universe cursor to this universe; otherwise preserve another universe's open slot/cursor |
| Class has no ready members in any universe | Clamp class credit to `LEAST(credit,0)`; set remaining=NULL, open universe=NULL, universe remaining=0 and universe cursor=NULL |

Apply idle clamping to affected attempt lanes even when this Job has no ready row, so a preceding refund cannot restore positive idle credit. Do not alter another universe's ready rows or candidate cursor. The standalone finalizer is not normal selected-head `dequeue`, which advances the candidate cursor to the removed sequence and would skip siblings during arbitrary cancellation.

Existing `releaseNotSentFairness` retains its one generation increment per actual revision-zero adjustment. The finalizer then increments each affected policy generation once if membership or idle state changed; a fully unchanged finalizer increments nothing. Thus one closure can legitimately advance a generation more than once. All increments are in the same transaction; no stale scheduler `Discovery` may subsequently be saved. Finally clear the Job lease and stamp the safely withdrawn Job. Any failure rolls the whole transaction back.

Increment the lease fence exactly once on a new idle withdrawal, rejecting overflow. The final Job CAS rechecks original status, epoch, fence and absence of a healthy lease. The trusted expiry CAS also checks its real database deadline. Request `withdrawn_at` only after all closure predicates are satisfied. Rollback restores readiness, counters, reservations, Steps and the Job together.

The helper returns `{status: 'cancelled'|'expired', changed: boolean, closedNotSent: number, preservedUnknown: number}`. An authorized replay of the same already-stamped terminal transition returns `changed:false`, zero mutation counts, and performs no new writes or clock change. Cancel replay still requires the original live session/current epoch. Expiry replay requires the original scoped Job/binding; no private record is recreated after retirement or Clear. A conflicting terminal reason or unstamped historical terminal row is ineligible. No separate cancellation request receipt is needed for this internal idempotent state transition. A future public cancellation API must define its own person-facing retry contract.

## Database guard

Main includes migrations0001–0010. Migration0011 will replace the withdrawal-clock guard, preserving all released files and its original live-lease branch. Use explicit non-overlapping branches: (1) the unchanged legacy old-live-lease guard, without new session or idle-fence requirements; (2) bound idle cancellation with a live current original session; (3) bound idle expiry with actual elapsed Job deadline and no liveness requirement. The idle branches permit only the scoped/bound direct queued-or-waiting transition with no healthy lease, exact fence advancement, no ready membership, terminal Steps, inactive Attempts and withdrawn accounting in `not_sent|unknown|responded`. Cancellation additionally requires the original session live/current; expiry requires the actual database deadline. The guard independently verifies current universe/Job/binding scope. These SQL checks protect storage shape; trusted database access is not a public authentication API.

Caller time is ignored in favor of `clock_timestamp()`. Existing stamped rows cannot change the clock/reason or reactivate. INSERT cannot supply a clock, and existing unstamped terminal rows cannot be backfilled. The accepted168-hour retirement delay and retained-accounting policy are unchanged.

## Fair scheduler integration

Current fairness expiry uses the ready request's earlier deadline to mark the whole Job expired. The new direct-bound path reads actual Job deadline under its locks. If the Job deadline has elapsed, perform the same safe expiry before acquiring scheduler resources in the probe; the helper itself locks the resource union and updates readiness exactly once. Return the ineligible observation immediately without invoking `dequeue`, `bypass`, `save` or any other write using the previous `Discovery`. Mark this probe explicitly as a terminal-expiry outcome. `schedule` must clear `lastProgress` for that outcome rather than assume `oldGeneration+1`, suppressing its final class-yield `save` even when maxProbes=1. The next probe discovers the new scheduler generation. Use one transaction for the entire closure. Never acquire new private locks after a scheduler lock. If only the ready request's deadline elapsed, dequeue that request with normal bookkeeping and leave the still-live Job queued; no automatic new request is created. A scheduler expiry savepoint is established after universe/session/Job locks and before helper-acquired locks. Only the closed permanent-refusal set `idle_graph_too_large`, `idle_incomplete_graph`, `idle_unsafe_attempt`, `idle_fence_overflow` may roll back fully to that savepoint and then use the existing cursor CAS plus non-removing bypass to advance an ineligible head. No partial closure writes survive. Binding/session/epoch, membership/count, CAS, missing-resource and arbitrary SQL failures abort the whole probe; the broader maintenance skip predicate is not a scheduler bypass whitelist. A healthy lease is checked before the savepoint and bypassed without withdrawal. Do not stamp an unbound/background Job through this new helper. Preserve the legacy out-of-scope behavior explicitly until its own lifecycle contract exists.

A third bounded lane in `createReasoningMaintenance` scans current-epoch original-bound direct queued/waiting Jobs whose real Job deadline has elapsed, including Jobs whose ready request was previously dequeued. It invokes the same expiry helper, so an early request deadline does not permanently strand its private graph. Expiry,168-hour private retirement and closed-accounting purge rotate with separate process-local keyset cursors, one candidate per transaction within the existing total1–128 probe budget. Initial lane is expiry, followed by private retirement, then accounting, repeating across batches. Advance the next-lane pointer before starting each transaction; advance its keyset cursor on candidate selection even when the probe later skips or rolls back. An abort before the first probe consumes no lane or candidate. Add required aggregate `expiredJobs:0` to every result (including abort-before-first); count only changed:true successful expiry commits, and update all exact-object callers/tests; retain universe `SKIP LOCKED`, statement/lock timeouts, advance-on-skip cursors, signal checks between transactions and no identity/payload logs. No healthy lease is interrupted. Oversized/missing/unsafe graphs are skipped, never partly closed. Reuse the existing128-Step/128-Attempt graph bounds before loading children. The separate maintenance process consumes the updated factory; its graceful shutdown and disconnect barrier stay unchanged.

This issue supplies internal closure, scheduler integration and bounded expiry maintenance. Source integration is not deployment to the running owner process; public cancellation UX and production scheduling remain separate.

## Verification and remaining decisions

Real disposable PostgreSQL checks cover queued and recovered unknown work; maintenance expiry after early ready-request dequeue, locked-universe progress and three-lane boundedness; original-session substitution, expiry and revocation; foreign/old epoch; competing claim/reserve/dispatch/recovery, session/resource lock waits, deadline recheck, rollback, arbitrary non-head removal and cursor preservation, refunds before idle clamping, maxProbes=1 final-yield suppression with/without fairness refunds, required batch counters/rotation/abort, readiness/debt preservation, raw clock/fence tampering, Clear, authorized replay,168-hour retirement and late original usage. Independent privacy/concurrency review and existing joined reasoning/cleanup regressions are required. No live provider call.

Fresh execution authority, completed/failed private retention, actual route/model/budgets and bounded paid experiments remain undecided separate gates. This engineering contract makes no policy decision on them and does not complete #72.
