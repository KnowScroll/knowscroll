## Implementation decisions

- Keep is a separate web collection using freshly reconciled existing Universe/Trace responses.
- Atlas includes System and local World inspection. World detail uses only source title/URL and
  exact encountered/total Scroll counts; it creates no new domain model or events.
- Coastline, grid and cloud textures are decorative (aria-hidden), never named semantic regions.
- Reference fonts are distributed locally with OFL licenses. Google Fonts upstream links and
  copyright texts are in `apps/web/public/fonts/`; the same binaries are used by Android.
- `FULLY EXPLORED` is replaced by literal encounter language. Age no longer enlarges saved Traces.
- System entry remains available with zero keeps: no saved items is not evidence of no encounters.
- Narrow/short web Atlas uses bounded flowing rows so its labels and navigation remain reachable.
- Existing sheet/source, retry, privacy-epoch and visible exposure rules remain authoritative.

## Integration findings (22 September)

- Web's 1440×420 layout let the heading intercept a Trace. Narrow/short layouts now use flowing
  rows. A queued scroll event from the former scroll owner also overwrote reading depth during a
  breakpoint change; it is now ignored. The reader itself is not given an entry transform.
- Desktop zoom is bounded at its fitted scale; zoom-out/in and recenter cannot enlarge markers
  beyond their fitted frame. Below 1024px the Atlas uses flowing rows instead of desktop geometry.
- Android's worker patch still put a FlowRow inside a clipped, fixed-height box. Integration removes
  that box and makes the entire collection reachable through the page scroll. The regression test
  scrolls to all 12 Trace labels and checks their actual horizontal bounds, not merely existence.
- The worker's `AnimatedVisibility(visible=true)` inside an `if` could not animate exit. World
  navigation now uses a reduced-motion-aware crossfade; the same source actions are not left
  accessible underneath a world overlay. Both clients share decorative coastline/grid geometry.
- The first native action was below the compact/large-text fold. It now precedes the map.
- Native foreground reconciliation reset System/Keep to Universe. Navigation retention now requires
  a fresh response confirming the same universe and privacy epoch; world data is fetched again.
  Scope change or failed authority still removes private content and returns to the safe state.
- Native date parsing is strict and localized. Tests set/restore their locale and timezone rather
  than assuming the machine uses US formatting. Clear's scope is explicitly the universe, not the
  device. Its existing confirmation and retry identity remain unchanged.
- The MiniMax M3 Android worker was stopped with a partial patch, not accepted as a completed delivery.
  Coordinator review/integration and real runtime checks are the acceptance evidence. Usage is
  recorded in `../journeys/evidence/ui-refinement-2026-09-21/workers.json`.

## Privacy counterexample found by the final native pass

While a world detail was open, the disposable universe was cleared through the real API and the
Activity resumed. The UI correctly removed its cached detail, but the API still returned the old
world system. This reproduced ADR-0028's known erasure gap. Migration 0025 and the existing
Clear/Reset transactions now remove only that universe's encounter-derived system and members,
after exposures. Shared catalog worlds/assets and neighboring universes survive. Exact Clear
receipt replay still precedes deletion, preserving newly encountered worlds after a retry.

ADR-0010, ADR-0028, ADR-0030 and the HTTP contract record this successor scope. Tests exercise
Clear, Reset, neighbor isolation, shared catalog preservation, exact retry after new activity,
conflicting retry and deletion refusal while exposures remain. The draft delivery calls out this
privacy contract change for #4 review before merge. No owner history was cleared or migrated.
