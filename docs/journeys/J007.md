# J007 — A gated Reel becomes inventory, offered only to a client that asks for it

J007 is the joined vertical-slice proof for [ADR-0025](../decisions/0025-eligible-reels-in-inventory.md)
and [issue #102](https://github.com/KnowScroll/knowscroll/issues/102), under #8/#9/#3/#72. It
follows [#100/J006](J006.md) (publication gates and media serving), reusing that journey's stand-in
seeding shape for one `generated_reel` rather than running a real Cutroom instance.

- **Desired outcome:** a Reel whose gates cleared becomes a real encounter, addressed like a Scroll:
  minting is idempotent; the default feed is unchanged for existing clients; a client that asks for
  `kinds=Scroll,Reel` is offered it, with the documented item shape; exposure, keep and the events
  lookup work identically to a Scroll (no new event kind); a kept Reel is excluded from later
  candidates; and its media streams back byte-identical to what was stored.
- **Selected architecture:** ADR-0025, migration 0015, `apps/worker/src/publication/mint.ts`,
  `apps/api/src/app.ts`'s `kinds`-aware feed, `packages/core/src/composer.ts`, `packages/contracts/
  src/inventory.ts`.
- **Expected runtime path:** seed one legitimate finished-video `generated_reel` (availability
  `imported`) → gate it to `test_eligible` (identical to J006) → mint its inventory asset → the
  default feed never includes it → `kinds=Scroll,Reel` offers it → expose → keep → the real
  deterministic projection worker reaches the Keep → the events lookup reports it projected → the
  same `trace` row exists → the Reel is excluded from later candidates → its media streams back
  byte-identical.
- **Observed runtime path:** matched exactly, on the run recorded below; 27/27 checks passed.
- **Evidence:** exact KnowScroll HEAD, Node and ffmpeg versions, the disposable database name, the
  generated Reel id, minted asset id and its media sha256/size, and a full pass/fail ledger are in
  the receipt written to `$KS_DEV_ROOT/inventory/logs/inventory-journey-<stamp>.json`; a sanitized
  snapshot lives at [`evidence/reel-inventory/`](evidence/reel-inventory/README.md).
- **Divergence and first failing boundary:** three real first-failures were found and fixed while
  building this slice (not journey-runtime instability) — see "First failures and corrections" in
  the evidence README.
- **Remaining decisions / next action:** none for this slice. Reel playback UI (mobile/desktop) is
  the named next slice; a real Visual Witness implementation remains the dependency before any Reel
  can be genuinely `eligible` (not merely `test_eligible`) in a real universe.

## Required evidence

| Boundary | Required observation |
|---|---|
| Minting | Idempotent per generated Reel (a second mint call changes nothing and returns the same asset id); refused for an ungated Reel; media/truth-state/simulated provenance guarded by the database |
| Default feed unchanged | `GET /v1/feed` with no `kinds` parameter never includes the minted Reel, even though it is eligible |
| Opt-in feed | `GET /v1/feed?kinds=Scroll,Reel` includes the Reel, with `mediaUrl`, `truthState`, `simulated`, `generatedLabel` all correct and no engine path anywhere |
| Unknown kind refused | `kinds=Scroll,Video` (or any malformed value) is `400`, never silently dropped |
| Exposure/keep parity | The same `POST /v1/exposures` / `POST /v1/interactions` routes work for a Reel; the real projection worker reaches the Keep; `GET /v1/events/:eventId` reports it projected; the same `trace` row is written — no new event kind |
| Kept exclusion | A kept Reel is excluded from later candidates, exactly like a kept Scroll |
| Documented boundary | `GET /v1/traces/:eventId` for a kept Reel returns the endpoint's own existing generic error (not a crash), because that endpoint's Scroll-only selection schema lives outside this lane's owned paths |
| Media serving | Authenticated `GET /v1/media/:sha256` returns the whole file byte-identical to what was stored, with the simulated-media marker present |
| Cleanup | The API process and the real projection worker both exit; no stray `knowscroll_test_inv_journey_*` database remains; the scratch media directory is removed; the owner database and the owner-local stand-in Cutroom engine on `127.0.0.1:4390` are never touched (this journey never starts, contacts, or dispatches to Cutroom at all) |

## Run

From the repository root:

```sh
. ./scripts/env.sh
pnpm exec tsx scripts/run-inventory-journey.ts
```

The journey creates its own disposable `knowscroll_test_inv_journey_<stamp>` PostgreSQL database
(migrated fresh from `packages/db/migrations/0001`–`0015`), seeds the bootstrap owner universe row
and one fully legitimate finished-video `generated_reel` row — going through migration 0013's own
admission and lineage guards, not around them — with a real, local-ffmpeg-made MP4 at its
content-addressed key. It starts three real, separate processes bound to explicit local
configuration: the KnowScroll API (`apps/api/src/main.ts`), the deterministic projection worker
(`apps/worker/src/main.ts`), and the one-shot publication-gate/mint CLI
(`apps/worker/src/publication/cli.ts`, run twice: `evaluate --decide test_eligible`, then `mint`).
Every child process receives an explicit, minimal environment (`DATABASE_URL`, `KS_MEDIA_ROOT`, and
for the API `KS_DEV_TOKEN`/`PORT`) — never this repository's own `.env`, never a provider credential
(this slice never holds one in the first place).

A full receipt is written to `$KS_DEV_ROOT/inventory/logs/inventory-journey-<stamp>.json`; a
sanitized snapshot and README (exact revisions, the full per-check ledger, first failures and
corrections) live at [`evidence/reel-inventory/`](evidence/reel-inventory/README.md).

## Limits

The `generated_reel` this journey mints from is seeded directly with a stand-in provider mode, not
produced by a real (even stand-in) Cutroom run — #94/J005 already proves that supply path, and
#100/J006 already proves the gate-evaluation/serving path this journey reuses unchanged.
`witness_alignment` is verified `unavailable` by construction (no Visual Witness model exists
anywhere in this codebase); this journey cannot and does not prove what a real witness implementation
would decide, nor does it prove anything can become genuinely `eligible` (only `test_eligible`) in a
real universe. **The dedicated Trace-revisit read endpoint (`GET /v1/traces/:eventId`) and the
Universe trace list are proven only to fail gracefully (their pre-existing generic errors, not a
crash) for a kept Reel** — that endpoint's Scroll-only selection schema lives in
`packages/db/src/trace-revisit.ts`, outside this lane's owned paths, and ADR-0025 explicitly defers
all Reel playback/revisit UI to a later slice. The HTTP round trip here uses the API's own bootstrap
development identity (`KS_DEV_TOKEN`), the same mechanism [bootstrap-http.md](../contracts/bootstrap-http.md)
documents; it is not a claim about production authentication. No owner deployment, owner acceptance,
or real generation is proved or claimed anywhere in this journey.
