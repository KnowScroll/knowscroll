## Implementation proof

`pnpm typecheck`; `pnpm test` creates and drops a fresh test database, verifies admission/duplicate conflicts, ownership at the dev boundary, selection vs exposure, atomic rollback and retry. Android compile/lint/tests are separate.

## Runtime/product proof

Run API and worker separately, then `pnpm verify:journey`. It consumes one unkept editorial asset and preserves history. It fails honestly on library exhaustion. Do not reset personal state to get a green receipt; use an isolated environment when repeating from a new universe.

On an Android emulator/device: open app → enter Scroll → inspect source and reason → Keep → return → observe retained Trace → reopen discovery → verify the kept asset is excluded. Confirm the same IDs in the database receipt. Also stop the API and verify visible retry without fabricated content/success; restore it and recover.

A source-backed paragraph and a working Keep do not prove improved mental models or the finished interaction grammar. Owner feedback and later longitudinal evaluation are separate evidence.
