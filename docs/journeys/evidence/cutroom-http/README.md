# Pinned Cutroom HTTP client — #86

[ADR0020](../../../decisions/0020-cutroom-http-client.md) adopts upstream238df854's wire schemas and implements an unwired loopback client. Seven source modules remain byte-identical to their recorded hashes. Local checks additionally enforce the actual server variation restriction, immutable prepared bytes, identity/stage/status/cursor consistency, bounded requests/responses, timeout/abort and redirect refusal. Returned paths remain metadata; the existing import port is not implemented.

[Release checks](release.json) passed typecheck and **474 backend tests** (12 baseline plus462 additional), including **30 local HTTP checks**. Client source was verified at `b2e2179`; the final full suite and process proof ran at clean `30b3c58`. Final runtime hashes are recorded. Tests cover exact body replay after caller mutation, lost submit acknowledgement, lookup404 without resubmission, declared result/refusal/error variants, changed run/request/stage/version, reference mutation during fetch, cursor regression/order, malformed data, bounded chunked reads, redirects, timeout and pre-/in-flight abort.

The [restart receipt](restart.json) launches separate synthetic HTTP-server and caller processes, saves the original prepared request before submit, commits a stand-in receipt then deliberately drops its HTTP acknowledgement. Both processes exit and are replaced; the new caller checks saved byte/digest equality and reconciles the original requestId without resubmitting. The persistent stand-in records **one submit, five reads and one cancel**. Each server acknowledges its graceful stop, all four processes exit and the temporary directory disappears without forced cleanup. Eleven process-source hashes match the final tree.

The initial process fixture assigned submit count1 on every POST. Coordinator review caught that this was insufficient evidence of no duplicate across restart; the final fixture increments prior state on repeated POST and explicitly answers replay/conflict. Only the corrected `30b3c58` receipt is accepted. This was a proof-strengthening change, not a demonstrated production retry defect.

MiniMax M3 supplied independent contract and implementation review. The coordinator inspected actual code, corrected review overclaims about uninspected upstream idempotency and result-storage interleavings, and executed the accepted checks. The [independent review record](independent-review.json) includes the final process-harness review and dependency versions. The stand-in repeated-POST/conflict branch is not executed by the single-submit restart journey; explicit replay bytes are separately exercised by the HTTP unit fixture. No reviewer ran the runtime tests on behalf of the coordinator.

All HTTP peers and all results are synthetic. There is no real generated media, paid-provider call, actual Cutroom deployment, product GenerationJob store, host import, publication, funding or owner acceptance. Stand-in persistence does not prove upstream durability or complete paid-attempt accounting. #9 and full-v1#72 remain open.
