# PostgreSQL disconnect before disposable teardown — #70

`pg-pool` 3.14.0 removes idle clients from its internal list before asynchronous `client.end` completes. Therefore its `pool.end()` promise can resolve while a PostgreSQL backend remains connected. The controlled before probe holds one real client disconnect, awaits pool end, and observes SQLSTATE `57P01` after a forced database drop. The after probe holds the same gate: the new helper fails its bounded wait while the backend remains, then succeeds after release and allows ordinary drop with no pool error.

This demonstrates a real teardown window, not the exact cause of old CI. `ci-before.json` and `ci-followups-before.json` retain the three observed failures on PR65 and main; those aggregate pool/admin errors and cannot identify origin, phase or SQLSTATE. The older missing-acknowledgement issue #57 remains open.

The 2.5-second wait has bounded queries and a conservative 50ms final-query budget; late completion can fail cleanup, never create a false pass. Forced removal remains a failing fallback.
