# Core ownership

Pure deterministic selection and validation live here. No database, HTTP, provider, or UI imports. As of ADR-0032/#133 the feed's default Composer is `composer-semantic-v3` (`src/composer/semantic.ts`): families over the reader's own recorded acts and the admitted substrate, hard gates (kept, on screen, suppressed by the reader), seen reranked in strict tiers (never gated), a rolling exploration floor, and every term size in its immutable policy row (`composer_policy.weights.terms`, guarded by a drift test); the caller records every considered candidate as `decision_candidate`. `composer-signals-v2` remains registered, immutable and selectable. Before ADR-0032 the Composer was `composer-signals-v2`: a versioned, immutable policy scores and diversity-ranks a signal snapshot (exposure count/recency, unread, source — nothing else) fetched by the caller (`packages/db/src/composer-signals.ts`) and renders one registered explanation per candidate; the caller persists that same output as `decision_signal` rows so a later reader can recompute and check it rather than trust it. Do not describe this as the target design's full multi-term utility engine — it is a deliberately smaller, SQL-primitive ranking (ADR-0028). Add cognitive utility, provenance and uncertainty through a further Composer issue and target design when one exists. Changing ranking requires a new policy version and journey evidence, never a code-constant edit to the scoring function. `composer-signals-v1` (migration 0019) predates the coverage tie-break added by `composer-signals-v2` (migration 0021, ADR-0029 amendment, #113): among candidates the score cannot separate, v2 prefers the source with fewer recorded exposures in this universe before falling back to v1's hash-of-`assetId` tie-break, so no source can sit behind another indefinitely. v1's row remains registered and immutable but is never loaded by any code path from here on.

`src/semantic/bridge-validator.ts` (ADR-0031) is the pure bridge validator: a closed rejection vocabulary, versioned as `bridge-validator-v1`. A rule change is a new validator version, never an edit that silently changes past decisions; `sliceReadSet` must keep re-deriving recorded decisions exactly.

`src/scrolls/` (ADR-0041) is the pure model-written Scroll boundary: `material.ts` (`material-hosts-v1`: the allowlist, OpenStax refused by name, the snapshot tool's visible-text rules) and `writing.ts` (the bounded request, the one-object reply, `scroll-checks-v1` with a closed reason vocabulary). A changed rule or bench number is a new version. `src/semantic/source-text.ts` is the one text normalization; `scripts/substrate/snapshot_source.py` mirrors it, and nothing else may copy it.
