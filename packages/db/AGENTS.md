# Persistence ownership

Append ordered numbered migrations. Never rewrite an applied migration or remove user history to get a test green. Coordinate shared schema changes before independent agents implement consumers. Tests use isolated databases. Ledger rows are source events; Accounts/Trace are rebuildable projections. Privacy lifecycle may erase payloads under a later explicit policy; append-only is not a promise to retain personal data forever.

ADR-0009 governs session hashing, expiry/revocation, ownership FKs and privacy epochs. ADR-0010 defines the bootstrap history-clear policy: authenticated universe lock, expected epoch, exact retry receipt, calling-session rollover, scoped FK-safe removal and monotonic revisions in one transaction. Do not retain deleted payloads in receipts or logs. Shared assets and unrelated universes survive. Full account deletion, backups and semantic reset have separate unresolved retention boundaries.

Read ADR-0012 before reasoning-runtime work: separate private execution and retained minimal accounting identities; universe-first locks; consumed dispatch intents are never replayable. A late old-epoch receipt may settle original accounting without private output authority. Exact history-clear receipt replay returns before any reasoning/accounting mutation. Migration 0004 and reasoning-storage.ts implement storage, history-clear erasure, restricted receipt append and bounded retention cleanup. Read docs/operations/reasoning-storage.md for caller transactions and remaining limits. Migration 0005 and the admission/reconciliation factories implement atomic development primitives. Read docs/operations/reasoning-runtime.md before consuming them: trusted resolver/context callbacks, immutable input/policy bindings, cumulative usage and no replay after ambiguous commit. J004 verifies synthetic process faults; product dispatch and scheduled cleanup remain unimplemented.
