# Persistence ownership

Append ordered numbered migrations. Never rewrite an applied migration or remove user history to get a test green. Coordinate shared schema changes before independent agents implement consumers. Tests use isolated databases. Ledger rows are source events; Accounts/Trace are rebuildable projections. Privacy lifecycle may erase payloads under a later explicit policy; append-only is not a promise to retain personal data forever.

ADR-0009 governs session hashing, expiry/revocation, ownership FKs and privacy epochs. ADR-0010 defines the bootstrap history-clear policy: authenticated universe lock, expected epoch, exact retry receipt, calling-session rollover, scoped FK-safe removal and monotonic revisions in one transaction. Do not retain deleted payloads in receipts or logs. Shared assets and unrelated universes survive. Full account deletion, backups and semantic reset have separate unresolved retention boundaries.

Read ADR-0012 before reasoning-runtime work: separate private execution and retained minimal accounting identities; universe-first locks; consumed dispatch intents are never replayable. A late old-epoch receipt may settle original accounting without private output authority. Exact history-clear receipt replay returns before any reasoning/accounting mutation. Migration 0004 and reasoning-storage.ts implement storage, history-clear erasure, restricted receipt append and bounded retention cleanup. Read docs/operations/reasoning-storage.md for caller transactions and remaining limits. Migration 0005 and the admission/reconciliation factories implement atomic development primitives. Read docs/operations/reasoning-runtime.md before consuming them: trusted resolver/context callbacks, immutable input/policy bindings, cumulative usage and no replay after ambiguous commit. J004 verifies synthetic process faults; product dispatch remains disabled. ADR-0015 below adds separate scheduled cleanup for safely withdrawn Jobs.

Migration 0006 and `reasoning-fairness.ts` implement internal durable fair admission. Read `docs/operations/reasoning-sql-fairness.md`: one probe transaction, universe-first locks, scheduler generation fencing, complete vector preflight, retained cross-epoch debt and immutable private ready rows. Shared scheduler resources lock before physical buckets; product dispatch remains disabled.

Migration 0007 and `reasoning-context.ts` implement internal session-bound direct Scroll compilation and concrete authority. Read `docs/operations/reasoning-context.md` and ADR-0014 before consuming it. Authenticate and compile on the same client/transaction; first compilation permanently binds that Job to its original session. Context locks precede scheduler/resources; post-resource rechecks acquire no new locks. Proposal/application and product dispatch remain absent.

Migration 0008/ADR-0015 define seven-day retirement only for safely withdrawn cancelled/expired Jobs. Read `docs/operations/reasoning-retirement.md`. Preserve the authoritative withdrawal clock, original live-lease requirement, immediate Clear History, and separate all-duties-closed accounting retention. The maintenance entrypoint is separate from projection; it must not release unknown liabilities, infer timestamps or broaden withdrawal authority.

ADR-0016/migration0009 add source-only explicit Ask facts. Read `docs/operations/explicit-asks.md` before consuming them. Authenticate on the same transaction, hold the universe lock, require the expected epoch before replay, preserve literal question bytes and original-session provenance, and let only Clear History erase the pair after epoch advance. The recorded_only receipt grants no queue/provider or V1 Keep-context authority.

ADR-0017/migration0010 add separate literal Ask context compilation. Read `docs/operations/reasoning-ask-context.md`. A recorded Ask grants no execution authority; compiler consumes only a separately authorized caller-supplied queued direct Job. Preserve original-session provenance, exact family routing and universe→session→Job→asset order. Post-resource rechecks acquire no new locks. Keep V1 stays Keep-only; retirement removes private bindings but preserves Ask source history until Clear.
